# intro-topic-bot

表向きは「定期的にお題を投下する bot」。裏では自己紹介チャンネルの投稿から専攻・興味を抽出し、**その人が話しやすそうなお題**を雑談チャンネルが静かなタイミングで投下する Discord Bot のプロトタイプ。自己紹介を見ていることは投稿から一切わからないようにする（見てる感を出さない）。

例: 専攻が哲学の自己紹介がある → 雑談チャンネルに

```
💭 今日のお題
**記憶をすべて失っても、その人は同じ人だと思いますか？**
-# 一言でも、リアクションだけでも歓迎
```

投稿の器は**毎回同じ**です（1行目 = `TOPIC_TITLE`、末尾 = `TOPIC_FOOTER` のサブテキスト。どちらも `.env` で変更可、フッターは空なら出ません）。お題の形式によって見出しや装飾を変えることはしません — 定期投稿は毎回同じ体裁で出るほうが自然で、雑談に混ざりやすいためです。問いの前には、良い導入文が作れたときだけ1文が入ります。

## セットアップ

### 1. Discord Bot の作成

1. [Discord Developer Portal](https://discord.com/developers/applications) → **New Application**
2. 左メニュー **Bot** タブ → **Reset Token** でトークンを発行（後で `.env` へ）
3. 同じ Bot タブの **Privileged Gateway Intents** で **MESSAGE CONTENT INTENT を必ず ON**
   （OFF のままだとメッセージ本文が空になり、何も動きません。最頻出のハマりポイント）
4. 左メニュー **OAuth2 → URL Generator**:
   - Scopes: **`bot` と `applications.commands` の2つ**
     （`applications.commands` が無いと `/topic` の登録に失敗します。2番目のハマりポイント）
   - Bot Permissions: `View Channels` / `Send Messages` / `Read Message History` の3つのみ
5. 生成された URL を開き、テストサーバーに招待
6. テストサーバーに `#自己紹介` と `#雑談` チャンネルを作成
7. Discord の設定 → 詳細設定 → **開発者モード** を ON にし、各チャンネルを右クリック → 「IDをコピー」

> **すでに招待済みのサーバーに `applications.commands` を足す場合**
> キックも作り直しも不要です。上記4の手順で `applications.commands` を含めた URL を生成し、**その URL をもう一度踏んで同じサーバーを選び直す**だけでスコープが追加されます。追加後は Bot を再起動してください（登録は起動時に1回だけ行うため）。

### 2. 運用ログチャンネル（任意）

`LOG_CHANNEL_ID` を設定すると、投稿・失敗・一時停止などの運用ログを色付きの embed で流します（緑=成功 / 灰=記録 / 黄=投稿しなかった・後で再試行 / 赤=人が対処する必要あり）。

そのチャンネルでは Bot に **Embed Links** も与えてください（**任意**）。無い場合は自動でプレーンテキストに落として送るので、ログ自体が消えることはありません。

### 3. Gemini API キーの取得（任意）

[Google AI Studio](https://aistudio.google.com) → Get API key。無料枠（gemini-3-flash: 10 RPM / 1,500 req/day）で十分動きます。

`GEMINI_API_KEY` は**未設定でも起動します**（定型お題モード）。その場合は自己紹介を読まず、内蔵の定型お題12件から直近と被らないものを選んで投稿します。キューや再利用プールは消費しないので、後からキーを設定すれば溜まっていた自己紹介からそのまま生成を始められます（`POOL_MAX_AGE_DAYS`（既定90日）を過ぎた本文は保持期限で削除されます）。本来の「自己紹介からお題を作る」機能を使うにはキーが必要です。

### 4. 環境変数

```powershell
Copy-Item .env.example .env
```

`.env` を開き、`DISCORD_TOKEN` / `INTRO_CHANNEL_ID` / `CHAT_CHANNEL_ID` を記入（この3つは必須。未設定だと起動時にエラーで止まります）。
自己紹介からお題を作らせるなら `GEMINI_API_KEY`（未設定なら定型お題モード）、管理コマンドを使うなら `OWNER_USER_ID`（自分のユーザー ID。未設定だと `/topic` は誰も実行できません）も設定します。
その他（投稿タイミング、見出しと末尾の一言、通知ロール、オプトアウトのリアクション、投票、`DRY_RUN` など）はすべて任意です。項目の意味と既定値は `.env.example` のコメントを参照してください。

### 5. 起動

```powershell
uv sync
uv run python bot.py
```

起動に成功すると、ログチャンネルに灰色の embed で「起動しました（DRY_RUN / 一時停止の状態・キュー件数）」が流れます。ローカル PC 運用で意図しない再起動に気づくための導線です。

### スラッシュコマンドが登録できなかったとき

起動直後にログチャンネルへ**赤い embed「スラッシュコマンドを登録できませんでした」**が出て、ローカルのコンソールにも同じ文言と traceback が出ます（多くは `Forbidden`）。原因はほぼ `applications.commands` スコープ無しで招待していることです。

復旧手順:

1. 「セットアップ 1. Discord Bot の作成」の手順4で `applications.commands` を含む招待 URL を作り直し、同じサーバーへ再招待する（キック不要。URL を踏み直すだけ）
2. Bot を再起動する（登録は起動時に1回だけ実行されます）

なおこのエラーが出ても Bot は起動を続け、**自動投稿・反応計測は通常どおり動きます**。復旧するまでの手動投稿は非推奨のフォールバック `!topic now` で行えます。

## 管理コマンド

運用者向けのスラッシュコマンド `/topic` を用意しています。応答はすべて **ephemeral（実行した本人にしか見えない）** です。

| コマンド | 用途 |
|---|---|
| `/topic now` | 投稿条件（時間帯・投稿間隔・静穏・一時停止）を無視してお題を1件投稿する |
| `/topic stats` | 形式ごとの件数・平均スコア・**現在の選択重み**、直近お題の「6h→24h」の反応、いま投稿できない理由 |
| `/topic queue` | キューの内訳（投稿可能 / 遅延待ち / 生成リトライ待ち）・再利用プール件数・計測待ち件数・前回の投稿時刻と投稿間隔が明ける時刻 |
| `/topic status` | いま効いている `.env` の設定（モード・チャンネル・投稿タイミング・静穏判定・計測・自己紹介の扱い）を読み取り専用で表示する |
| `/topic backfill [limit] [apply]` | 過去の自己紹介を再利用プールへ取り込む。既定はプレビューのみ（後述） |
| `/topic pause` | 自動投稿を一時停止する（`state.json` に永続化するので再起動でも解除されない） |
| `/topic resume` | 自動投稿を再開する |

- コマンド一覧に表示されるのは **Manage Server 権限を持つメンバーだけ**です（一般メンバーには存在自体が見えない = ステルス設計の維持）
- 実行できるのは **`OWNER_USER_ID` 本人だけ**です。他の管理者が打っても ephemeral で拒否理由が返ります（無言では終わりません）
- **`OWNER_USER_ID` は事実上必須**です。未設定（空 / 0）だと誰も `/topic` を実行できず、起動時に warning ログが出ます
- `/topic pause` が止めるのは**自動投稿だけ**です。反応の計測・新規自己紹介のキュー取り込み・`/topic now` は動き続けます
- `/topic status` は**表示だけ**で、設定の変更はできません（変更は `.env` を書き換えて再起動）。トークンと API キーの値は出力しません（設定されているかどうかだけを表示します）
- `!topic now`（オーナーの発言によるトリガー）は**非推奨**です。スラッシュコマンドの登録が本番で失敗したときの唯一の制御経路として残しているだけで、**次のラウンドで削除します**

### `/topic backfill`

導入初日から過去の自己紹介を活用するためのコマンドです。`#自己紹介` の最新 `limit` 件（未指定なら `.env` の `BACKFILL_SCAN_LIMIT`、既定200）を遡り、使えるものを**再利用プール**へ取り込みます。

- **二段階実行**: 既定の `apply:False` はプレビューのみ（件数を数えるだけで `state.json` を変更しない）。内容を確認してから `apply:True` で取り込む
- `DRY_RUN=true` の間は `apply:True` を指定しても**強制的にプレビュー**になります（「DRY_RUN は state を一切変更しない」保証を崩さないため）
- 応答は「走査N / 追加n / 重複a / 期限超b / 🚫c / 短文d」の内訳。除外の内訳は `state.json` に書かないので、同じ範囲を再実行しても取り込み済みが「重複」に増えるだけです
- 除外されるもの: Bot の発言 / 既に処理済み・キュー・プールにあるもの / `POOL_MAX_AGE_DAYS`（既定90日）より古いもの / 🚫 リアクション付き / `MIN_INTRO_LENGTH` 未満の短文
- 取り込み先は**キューではなくプール**です。キューは古い順×48時間間隔で消費するため、大量に積むと新規の自己紹介が何ヶ月も後回しになってしまいます。プールなら「新規キュー優先 → プール」の順序が保たれ、取り込んだ分は未使用（`used_count=0`）なので既存のプール項目より先に使われます

## 動作確認

### Gemini 部の単体確認（Discord 不要）

```powershell
uv run python try_gemini.py                 # 内蔵サンプル（文系/理系/趣味のみ）で5形式を1周
uv run python try_gemini.py "自己紹介文..."  # 任意テキスト
```

指定した形式・LLM が申告した形式・自己批評（審査）の合否と理由・投票の選択肢と、既定タイトルでの投稿イメージが表示されます。
確認観点: 問いに専門用語が含まれていないか、学校名・本名などが漏れていないか。
このコマンドは Gemini を直接叩くため `GEMINI_API_KEY` が必須です（未設定だとエラーで終了します）。

### ユニットテスト（Discord / Gemini を呼ばない）

```powershell
uv run pytest -q
```

静穏判定・候補選択・形式の重み計算・反応計測の時点判定・お題の文面組み立て（固定の器・ロールメンション）・定型お題の選択・ログの色分け・管理コマンドの整形・キュー投入（同一著者の置換）・バックフィルの判定・`state.json` の読み書きを検証します。

### E2E（テストサーバー）

`.env` の閾値を短縮してから起動すると数分で一巡確認できます:

```
MIN_DELAY_MINUTES=1
QUIET_MINUTES=1
POST_INTERVAL_HOURS=0
POST_WINDOW_START=0
POST_WINDOW_END=24
```

**基本動作**

1. `#自己紹介` に50文字以上の自己紹介を投稿 → 数分以内に `#雑談` へお題が投稿される
2. Bot を再起動 → 同じ自己紹介が再処理されない（`state.json` の `processed_ids`）
3. Bot 停止中に自己紹介を投稿 → 起動後に補完されて処理される
4. `#雑談` で発言し続けている間は投稿されず、静かになってから投稿される
5. `GEMINI_API_KEY` を壊して起動 → 黄 embed（次のリトライ時刻付き）が出てキューに残る（5分後→20分後と間隔を空けて再試行し、3回失敗で破棄）。**その周回は内蔵の定型お題が代わりに投稿される**（投稿が途切れない）
6. `GEMINI_API_KEY` を空にして起動 → コンソールのログに「定型お題モードで動作します」が出る。`/topic now` で内蔵の定型お題が投稿され、キューと再利用プールは消費されない（キーを設定して再起動すれば、溜まっていた自己紹介からそのまま生成が始まる）
7. キューが空の状態で `POST_INTERVAL_HOURS=0` → 過去の自己紹介（プール）由来、それも無ければ自己紹介を参照しない汎用お題が投稿される
8. `#自己紹介` の投稿に 🚫（`OPTOUT_EMOJI`）を付ける → その自己紹介は使われず破棄される
9. 自己紹介を編集 → 編集後の内容でお題が作られる / 削除 → 破棄されて次の候補に進む
10. 同じ人が `#自己紹介` に2回目を投稿 → キューの古い方が消えて新しい方に置き換わる（`/topic queue` の件数が増えない）。すでに一度お題に使われた分（再利用プール）は残る
11. 二択形式（choice）のお題 → Discord の投票が立つ（`USE_POLL=false` で無効化）
12. `DRY_RUN=true` → 実際には投稿されず、投稿予定の内容がログと `LOG_CHANNEL_ID` のチャンネルに出る（`state.json` も変化しない）

**投稿の見た目**

13. どの形式のお題でも1行目は同じ `TOPIC_TITLE`（既定「💭 今日のお題」）で、問いが太字になる。形式によって見出し・装飾が変わらない
14. `TOPIC_FOOTER` を設定 → 末尾にサブテキスト（小さい薄字）で表示される。空にすると行ごと消える。`TOPIC_TITLE` を変更 → 1行目が変わる（どちらも変更後は再起動が必要）
15. 投票形式のとき、本文はタイトル（＋導入文＋サブテキスト）だけで、問いは投票側に入る（本文に問いが二重に出ない）
16. （任意）`TOPIC_PING_ROLE_ID` に通知用ロールの ID を設定 → 本文の先頭にロールメンションが付き、そのロールを持つ人にだけ通知が飛ぶ。**サーバー設定でそのロールの「@mention を許可」を ON** にしないと文字列は出ても通知が飛ばない。`DRY_RUN=true` のプレビューにはメンションではなく「通知: ロールID=…」の注記だけが出る（ログチャンネルで実際に通知が飛ばないようにするため）

**管理コマンド**

17. `OWNER_USER_ID` に自分の ID を設定 → `/topic now` で時間帯・間隔・静穏を無視して即投稿される
18. Manage Server 権限のない別アカウントには `/topic` が一覧に出ない。運用者には見え、応答は本人にしか見えない
19. `OWNER_USER_ID` を未設定（空）にして起動 → `/topic stats` などが ephemeral で「未設定のため使えない」と理由を返す（無反応にならない）
20. `/topic now` を5分ワーカーの発火と重なるタイミングで打っても、お題が2連投されない
21. `/topic pause` → 定期投稿が止まる（`/topic stats` の「状態」に表示・ログチャンネルに灰 embed）→ **PC を再起動しても一時停止のまま** → `/topic resume` で再開する
22. `/topic backfill`（プレビュー）→ 件数を確認 → `apply:True` で取り込み → もう一度実行すると全件が「重複」になる。🚫 付きの自己紹介は除外され、取り込んだ分はプールに入る（新規キューがあればそちらが優先される）
23. `/topic status` → `.env` を書き換えて再起動すると表示が変わる。トークンと API キーの値は出ない（`GEMINI_API_KEY` を空にすると「定型お題モード」と表示される）

**反応の計測**

24. 投稿されたお題にスレッドを立てて発言 → 計測時の「返信」に加算される
25. 2点計測: `MEASURE_AFTER_HOURS=0` にして起動 → 即座に1点目が記録される → `state.json` の該当 `pending_measurements` の `posted_at` を25時間前に書き換えて再起動 → `at_hours=24` の行が追記され、その pending が消える

**運用ログ**

26. 投稿=緑 / `DRY_RUN`=黄 / **生成失敗の1回目で黄 embed（次のリトライ時刻付き）がすぐ出る** / 一時停止・バックフィル・起動通知=灰
27. ログチャンネルの Embed Links 権限を外す → embed ではなくプレーンテキストでログが流れる
28. Bot を起動する → 灰 embed の起動通知（DRY_RUN・一時停止・キュー件数）が出る

確認後、閾値を既定値（30 / 15 / 48 / 19 / 22）に戻すこと。

## 本番切替チェックリスト

テストサーバーでの検証が済み、本番サーバーへ向ける前に上から順に確認します。

1. **再招待と権限**: `applications.commands` を含む URL で本番サーバーへ招待し直す。Bot 権限は `View Channels` / `Send Messages` / `Read Message History` の3つ。ログチャンネルを使うならそこに `Embed Links` も（任意）
2. **MESSAGE CONTENT INTENT が ON** になっていること（OFF だと本文が空で何も動きません）
3. **`.env` を本番値に**: `INTRO_CHANNEL_ID` / `CHAT_CHANNEL_ID` / `OWNER_USER_ID` / `LOG_CHANNEL_ID`。あわせて **E2E 用の短縮値が残っていないか**を確認（既定は `MIN_DELAY_MINUTES=30` / `QUIET_MINUTES=15` / `POST_INTERVAL_HOURS=48` / `POST_WINDOW_START=19` / `POST_WINDOW_END=22`）
4. **`state.json` をバックアップしてから空にする**（ファイルごと退避して削除）。テストサーバー由来の `message_id` は本番では全件 NotFound になり、テスト中の `topic_stats` が形式の重み学習と few-shot を汚染するためです
5. **煙テスト**: `uv run pytest -q` が緑 / `uv run python try_gemini.py` でお題の文面と秘匿（専門用語・学校名・本名が出ていないか）を確認
6. **`DRY_RUN=true` でソーク**: 数日流してログチャンネルの黄 embed で文面と投下タイミングを確認 → 問題なければ `DRY_RUN=false`
7. **異常時の一次対応を決めておく**: まず `/topic pause` で自動投稿を止め、ログチャンネルの**赤 embed**（人が対処すべき事象）を確認する

> **注意: `MEASURE_AFTER_HOURS` は運用開始後に変えないこと**
> 形式の重み学習と few-shot は「`MEASURE_AFTER_HOURS` と同じ `at_hours` の計測行」だけを見ます。運用途中でこの値を変えると過去の計測行がすべて対象外になり、**学習が実質リセットされます**（重みは全形式 1.0 に戻り、few-shot も空になります）。

## 運用のコツ

Bot 側の設定ではなく、**返信が付くかどうかを左右する運用側の話**です。

- **投稿されたら運営が一言目を返す**。誰も返していないお題に最初の返信を書くのは心理的ハードルが高く、逆に1件でも返信が付いていれば続きます。`LOG_CHANNEL_ID` を設定しておくと投稿のたびに**緑の embed**（「お題を投稿しました」＋お題の本文）が流れるので、これを「投稿されたよ通知」として使い、見かけたら `#雑談` に一言返しに行く運用にすると効きます。運営の返信は Bot の投稿とは無関係の普通の発言なので、ステルス設計も崩れません
- **通知が欲しい人向けにオプトインロールを用意する**。「お題通知」のような自己付与ロール（ロールメニュー等で本人が付け外しできるもの）を作り、その ID を `TOPIC_PING_ROLE_ID` に設定すると、お題投稿の先頭にそのロールへのメンションが付きます。**サーバー設定でそのロールの「@mention を許可」を ON** にしておくこと（OFF だと文字列は出ても通知が飛びません）。全員に通知が飛ぶ設計ではないので、興味のない人には従来どおり静かなままです。既定（空 / 0）では無効です
- **お題ごとのスレッド自動作成は意図的に採用していません**。スレッドを開く一手間が挟まるぶん「一言だけ返す」が減り、雑談チャンネルの流れからも切り離されてしまうためです。返信は本文への直接リプライで受けるほうが、他のメンバーの目にも触れます

## 仕組み

```
#自己紹介 に投稿
  → on_message で検知し state.json のキューへ
    （Bot停止中の分は、起動時に前回の確認位置以降を最大50件まで履歴から補完）
  → 5分ごとのワーカーが毎回:
      ・保持期限（POOL_MAX_AGE_DAYS=90日）を過ぎた自己紹介本文をプールとキューから削除
      ・投稿から6時間後（MEASURE_AFTER_HOURS）と24時間後（MEASURE_FINAL_AFTER_HOURS）の
        2時点でお題の反応を集計（0 にすると1点計測に戻る）
        返信＝直接リプライ＋お題に立ったスレッドの発言数
        最終計測から MEASURE_GIVEUP_HOURS（72時間）過ぎても取れないものは諦めて破棄
    そのうえで、全条件を満たしたときだけ1件投稿:
      ・/topic pause による一時停止中でないこと
      ・前回のお題投下から48時間経過（2日に1回の定期お題を装う）
      ・19:00〜22:00 JST の投稿時間帯内
      ・#雑談 の静穏判定（Discord の返信ラグを考慮）:
          直近60分に3件以上発言 =「会話中」→ 45分静かになるまで待つ
          それ未満 =「まばら」→ 15分でOK
  → ネタを3段構えで選ぶ（新規が無い週もお題が途切れないように）:
      ① 新規キュー: 古いものから順に（30分未経過・リトライ待ちは除外）
      ② 再利用プール: 使用回数が少ない順 → 最後に使ったのが古い順
      ③ どちらも無ければ、自己紹介を参照しない汎用お題
  → 選んだ自己紹介は生成の直前に元メッセージを取り直す:
      🚫 リアクションあり / 削除済み / 編集で短くなった → 破棄して次の候補へ
      編集されていた → 最新の本文で生成（取得失敗時は破棄せず今回だけ見送り）
  → お題の形式を「直近2回と違う形式」の中から重み付き抽選で選ぶ
    （二択対立 / 経験共有 / 価値観 / あるある / 仮定 の5形式）
    重み = (2×全体平均スコア + その形式のスコア合計) / (2 + その形式の件数)
    → 反応が良かった形式ほど選ばれやすく、観測が少ない形式は平均並みに扱って探索を続ける
  → Gemini (gemini-3.5-flash) で抽出+検索+お題生成
    → 別コールで自己批評（正解がない・専門知識不要・一言で答えられる など7観点）
    → 不合格なら理由を添えて1回だけ作り直す（それでも不合格ならログに残して投稿）
    → 生成に失敗した回・GEMINI_API_KEY 未設定のときは、内蔵の定型お題（12件。直近と
      被らないものを抽選）に切り替えて投稿する。定期お題として途切れさせないため
  → 毎回同じ器で #雑談 に投稿:
      TOPIC_TITLE（既定「💭 今日のお題」）→ 導入文（あれば）→ **問い**（太字）
      → TOPIC_FOOTER（あればサブテキスト -# で表示）
      TOPIC_PING_ROLE_ID があれば本文の先頭にロールメンションを1行足す
      二択形式なら Discord の投票として投稿（問いは投票側に入るので本文には入れない）
      （本人への言及・メンションなし。自己紹介由来であることは出さない）
  → 投稿を計測待ちに登録。6時間後（MEASURE_AFTER_HOURS）の計測行のうち、
    反応スコア（返信×3 + 投票×2 + リアクション）が 0 より大きい上位3件は、
    次回以降のプロンプトに「反応が良かったお題の例」として還元される
```

投稿処理は `asyncio.Lock` で直列化し、ワーカー経路はロックを取ってから投稿条件を再判定します（`/topic now` の生成中にワーカーが発火して2連投になるのを防ぐため）。

**コミュニティへの寄せ方**: サーバーの傾向（学生が中心で、AI に興味がある人が多い）は、問いの**前提ではなく題材選びのヒント**として扱います。誰でも答えられる問いのうち、この人たちが特に答えを持ちやすい題材（AI との付き合い方・新しいものの試し方・学び方など）を選ぶだけで、その属性がない人が答えられない問いにはしません。AI を題材にする回も知識や是非は問わず、「AI と関わる自分の日常の行動・感覚」を聞く形にします。講義・試験・サークルのような学生特有の場面も前提にしません。AI ネタへの偏りは、上記の多様性ルール（直近のお題が AI 関連なら別の切り口を選ぶ）で抑えています。

## ファイル構成

| ファイル | 責務 |
|---|---|
| `bot.py` | エントリポイント。検知・補完・静穏判定・候補選択・投稿・反応計測・管理コマンド・運用ログ |
| `topic_generator.py` | Gemini 呼び出し（Discord 非依存）。生成と自己批評 |
| `prompts/` | `system.md`（お題の書き方・秘匿ルール・品質基準）と `judge.md`（審査基準）。コードを触らずに文面だけ調整できる |
| `store.py` | `state.json` の読み書き（アトミック保存） |
| `config.py` | `.env` の読み込みと検証 |
| `try_gemini.py` | Gemini 部の単体確認 CLI |
| `try_judge.py` | `judge.md` の回帰確認 CLI。固定のお題を審査させて期待合否と突き合わせる |
| `tests/` | pytest。Discord / Gemini を呼ばないロジックのテスト |
| `proposal.md` | Bot 運用者向けの組み込み提案資料 |
